# Примеры: один универсальный набор — разные проекты

Это **иллюстрации**, а не реальные назначения и не команды изменять действующие репозитории.

## A. ChemSim: приложение с научными расчётами

Проектные (не универсальные) назначения могут быть:
- A1 — Chemistry Data & Domain;
- A2 — Equation Parser & Balancer;
- A3 — Aqueous Chemistry & Equilibrium;
- A4 — Kinetics & Numerical Solver;
- A5 — координация интеграции и Godot-части в соответствии с **существующими** проектными полномочиями.

Важно: применение нового универсального A5 к уже работающему ChemSim требует отдельной согласованной адаптации: **v2 сама не повышает полномочия его текущего A5**. У ChemSim могут действовать собственные правила утверждения спецификаций.

## B. Backend/CLI без UI

Проект может назначить A1 — CLI, A2 — серверные операции, A3 — storage, A4 — тестирование/обработка ошибок; A5 — архитектуру и интеграцию. Никакой обязательный UI не создаётся. Отсутствие PR/CI при разрешённом локальном прототипе не блокирует автоматически выполнение задачи.

## C. Исследование или документация

Проект может назначить A1–A4 независимые исследовательские разделы, а A5 — сравнение результатов, устранение противоречий и сборку отчёта. Вместо проверки кода используются источники, воспроизводимость расчётов, фактологическая сверка и приёмка текста. Наличие исполняемого ПО не требуется.

## Проверка здравого смысла

Для каждой постановки ответь:
1. Можно ли назначить каждого A1–A4 без изменения его базового промпта?
2. Обязан ли агент создать ненужный GitHub-процесс, UI или новый approval gate? **Нет.**
3. Обязана ли команда проверять результаты подходящим способом и честно сообщать об ограничениях? **Да.**
4. Получает ли A5 права на публикацию, расходы или смену целей только из своего ID? **Нет.**
5. Может ли A5 без постоянных повторных вопросов руководить техническими задачами в уже разрешённой области? **Да.**
