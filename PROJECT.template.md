# PROJECT.template — необязательная памятка для проекта

**Это пример формата, не обязательный файл и не новый gate утверждения.** Если проект уже хранит эти сведения в AGENTS.md, OpenSpec, Issue или других инструкциях, используй их. Утверждение/статусы включай только тогда, когда процесс проекта действительно этого требует.

## Минимальный контекст для назначенной работы

- **Проект и цель:** <что создаём / что исследуем>
- **Текущая задача / ожидаемый результат:** <что должно быть получено>
- **Критерии готовности:** <как отличить готово от не готово>
- **Роли A1–A4:** <чёткое назначение каждого; допустимо N/A для неиспользуемых агентов>
- **A5:** <границы технической координации и делегированные полномочия>
- **Важные ограничения и решения владельца:** <запреты, утверждённые требования, применимые gates>

## Когда применимо

- **Репозиторий, ветки и инструменты:** <пути / Git / Issue / среда> либо N/A.
- **Архитектура, границы модулей, контракты:** <владельцы, потребители, правила изменения> либо N/A.
- **Зависимости и согласование параллельной работы:** <что пересекается и кто координирует> либо N/A.
- **Тесты/проверки и сдача:** <команды, среда, допустимые ограничения, reviewer> либо N/A.
- **Внешние операции и доступы:** <что разрешено, что требует отдельного разрешения> либо N/A.
- **Версия первичных промптов:** <Git SHA/версия> — рекомендуемое поле для длительных команд.
- **Публикация/релиз:** <кто решает и при каких условиях> либо N/A.
- **Статус утверждения, подпись или ссылка на решение:** <если проект использует approval gate> либо N/A.

## Назначения

| Агент | Функция в этом проекте | Область и артефакт | Зависимости / критерий |
|---|---|---|---|
| A1 | <назначение> | <границы> | <проверка> |
| A2 | <назначение> | <границы> | <проверка> |
| A3 | <назначение> | <границы> | <проверка> |
| A4 | <назначение> | <границы> | <проверка> |
| A5 | Главный технический координатор | <интеграция/координация в пределах разрешений> | <готовность> |

**Не нужно заполнять всё ради формы.** Достаточно точной и понятной постановки для разрешённой работы. Отсутствие неиспользуемых технологий, CI, PR, UI и прочих условных элементов **не является блокером само по себе**.
